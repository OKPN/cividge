ブラウザで変換し、自分のストレージへ直接保存・配信

Cividge

❓ どのようなサイト？
Civitai Bridge（Cividge）は、ブラウザ内でメディアを変換し、自分の Cloudflare R2 または Filebase（IPFS）へ保存・配信する個人用アップローダです。
必要に応じて KV Worker により別名 URL・期限・閲覧パスワードを管理でき、Kubo ノードは IPFS コンテンツの保全先として利用できます。

IPFS のパスワード保護について
※ パスワードは Cividge の配信 URL を保護します。IPFS の CID を知る人は、IPFS Gateway 経由で直接取得できる場合があります。秘匿が必要なファイルは投稿しないでください。
📚 KV 配信・管理 Worker

R2 / Filebase 共通の短縮 URL、別名リンク、有効期限、パスワード保護を管理する台帳です。

⚡ Cloudflare R2

R2 の接続情報、R2 専用の配信ドメイン、CORS と容量解放を設定します。

🪐 Filebase (IPFS)

Filebase の CID・IPFS 保存、Filebase 専用配信ドメイン、CORS を設定します。

🏠 自宅 Kubo (IPFSノード永続保存)

自宅 PC / サーバーの Kubo ノードと連携し、R2 や Filebase の容量解放時にファイルを自動保全します。

1️⃣ R2 の公開・配信 URL を設定 * 必須
※ R2 用の Worker URL、pages.dev URL、独自ドメイン、R2 dev URL を何件でも追加・削除できます。選択された URL が画像コピーやパレットの配信ベース URL に使用されます。
配信 URL の作り方・変更方法
最初は KV Worker の https://…workers.dev をそのまま使えます。独自の URL が必要な場合だけ、Pages をデプロイするか Worker に独自ドメインを追加します。
🛡️ pages.dev 公開互換レイヤー（ランダムクエリ防御）
静的リレープロジェクトを設置する
同梱テンプレートを公開用の静的 Pages プロジェクトとしてデプロイします。作成された pages.dev URL を上の R2 配信ドメインに追加して選択してください。
2️⃣ Filebase の公開・配信 URL を設定 * 必須
※ Filebase / IPFS 用の Worker URL、pages.dev URL、独自ドメインを何件でも追加・削除できます。選択された URL が Filebase への新規投稿の配信ベース URL に使用されます。
配信 URL の作り方・変更方法
Filebase 用には R2 と異なる配信ドメインを使います。新しい Pages プロジェクトを作成し、この Cividge の配信コードをデプロイしてください。
🛡️ Stable public URL layer (optional)
Install the static relay project
Deploy the included static template as the public Pages project. It contains no Functions, KV, or storage credentials; it redirects each path to the compatibility Worker. Add the resulting pages.dev URL to the Filebase delivery-domain list above and select it. There is no per-upload switch.
Recommended Cloudflare settings
For a compatibility Worker on your own domain, add a small URL Rewrite Rule that removes query strings while preserving the path. For steady public delivery, also rate-limit the internal /r/ path.
⚡ Cloudflare R2 接続情報 (S3 API) Cloudflare ↗
R2 バケットの CORS 設定（ブラウザから接続するため必須）

R2 → 対象バケット → Settings → CORS Policy → Edit に、フロントエンド URL を許可するポリシーを貼り付けます。配信ドメインではなく、このアプリを開く URL を指定します。

これは何をする機能？
自分の PC / サーバーを IPFS ノードとして使い、Filebase の容量解放前に CID を Pin して残します。Kubo が正常に稼働し Pin データを保持している間は、その CID の実体を自分でも保全できます。これは保存の保全層であり、唯一のバックアップにはしないでください。

                            
最小セットアップ
1. Kubo をインストールして起動する。 2. この欄は自宅では http://127.0.0.1:5001 のままにする。 3. 🔌 接続テストに成功してから「Filebase容量解放時にKuboへ自動Pin留め」を有効にする。Kubo がオフラインなら、Cividge は Filebase FIFO を安全のため停止します。

                            
配信とキャッシュ
Cividge の配信 URL はエッジキャッシュを使うため、キャッシュ済みのアクセスは Filebase や IPFS ノードへの負荷を抑えます。ただし、初回アクセスやキャッシュ失効時には上流へのアクセスが必要です。Kubo RPC は Pin 操作用であり、これだけで常時配信の第1オリジンになるものではありません。

                            
保管の考え方
自動 Pin の対象は Cividge が容量解放する Filebase の CID です。任意の CID を無制限に Pin する用途にはせず、Kubo の保存先と空き容量を定期的に確認してください。PC 故障・削除に備え、重要データは別のバックアップや Pin サービスにも残します。

                            
安全な接続
API は通常 127.0.0.1:5001 に限定し、インターネットへ直接公開しないでください。外出先や別ネットワークから Pin 操作をしたい場合は、ポート開放ではなく Tailscale Serve などで Tailnet 内だけに公開した HTTPS エンドポイントを使えます。その URL を上の RPC エンドポイントに設定します。0.0.0.0:5001、一般公開のリバースプロキシ、ルーターのポート開放は使用しないでください。
